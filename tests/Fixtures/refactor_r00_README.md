# R00 脱敏故障夹具

数据文件：[refactor_r00_incidents.json](refactor_r00_incidents.json)。任务证据：[XNR-001](../../docs/development/reports/XNR-001-baseline.md)。

用途：让后续 R01–R05 的新合同回归不依赖已经清空的旧小说数据库。本文件不是可直接导入业务库的种子，也不是已经通过的自动测试。

## 来源与边界

- R00-001–006 是保留数值、结构或错误事实的历史观测投影。完整请求/响应只在本机历史日志，仓库只保存关联 ID、日志位置和响应体的规范化 JSON SHA-256，不保存凭据或整章正文。
- R00-007–017 是明确标记 `synthetic_contract` 的人工构造场景。它们表达新版预期，不伪装真实 Provider 响应。
- `expected_target` 是目标行为。当前实现可能不满足，不能因为 JSON 可解析就宣称新版通过。
- 原始数据库中的 Run/Artifact/Review/Usage 已清空。failed_jobs 与日志同类错误能够互相印证，但未恢复的关联不能当成完整数据库来源链。
- 历史日志混有测试/管理活动，不能将日志事件数量当作生产失败率。HTTP 200 只证明日志记录了正常响应，不证明业务审校合格或供应商账单已结算。

## 使用方式

后续测试用 `json_decode(file_get_contents(...), true, flags: JSON_THROW_ON_ERROR)` 或测试语言等价 JSON 解析读取 `cases`，按稳定 `id` 取样；测试自行创建隔离数据库记录并映射样本来源。不得使用历史 `run_ids` 或 failed_jobs ID 作为当前数据库外键。

数值/审计数组场景可以纯函数验证。重复投递、提交回滚、主任务唯一性、预留金额并发等必须在 XNR-003 提供的隔离 PostgreSQL/Redis 环境验证。R00 没有搭建这些环境，也没有证明这些业务路径通过。

所有场景带中文说明。若将夹具转成 PHP 构建器或增加测试代码，按任务规范增加中文注释；测试数据不带真实人名、原小说名、账号、密钥、私有服务端点或绝对工作区路径。
