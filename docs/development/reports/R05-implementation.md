## 2 正式写入与恢复边界

- 小说、任务、章节按统一锁序串行；正式提交再次检查控制版本、同源产物、校验和、当前状态、独立 PASS 及硬规则。事件、事实候选应用、状态、指针和提交凭证全部成功或全部回滚。新链复用现有状态应用器，不把所有叙事自动转换成 Fact。
- 提交与摘要准入分开事务，提交事务内已登记摘要待办。摘要失败保留正式正文；对账只补摘要与缺失派生，不再次提交、重写或清零费用。摘要绑定正式正文证据后才进入下一章。
- 向量是派生能力：同书正式来源、内容 hash、模型/维度、租约检查；费用仍由原 Task/Usage 追踪。正式状态或必需摘要不全不能降级绕过；仅向量不足时允许可解释 SQL 召回。
- 80% 目标进入收束约束，达到目标后正式证据审计；没有原文证据不能判定承诺兑现。审计输入采用有限正式摘要集合，避免全文入 Prompt；真实长篇召回/结局质量仍需 R06 验证。
- 正文完结与任务完成分开。导出冻结全清单和标记，逐章读取正文并核对 hash，同目录临时文件完整写入后发布；最终核对实际文件 hash 才完成任务。丢失/损坏只重建导出，不产生模型费用。
- 最近章撤回需暂停与原因，追加恢复 StateVersion/OperationRecord，失效对应事件/记忆及后续候选；恢复重新规划同一章，旧审校不能复用。历史产物和费用保留。
