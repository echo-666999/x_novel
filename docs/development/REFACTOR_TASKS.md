## 1 执行边界与任务使用方法

目标是一段概述自动生成完整小说，采用三层规划、容量允许时整章写作、必要时顺序拆分、独立提取/审校和事务正式提交。旧小说仅提供经验与脱敏样本，不做迁移或兼容续跑；新版产生的历史、费用、状态和产物必须保留可追溯性。

PRD 记录的旧 `AGENTS.md` 已删除，不恢复旧长篇业务规则作为前置步骤。本文件编制末次检查时，该路径已重新出现 Laravel Boost 指引，依赖锁文件和前端资源也出现工作区变更；这些不属于本次文档改动。执行前读取届时有效的开发指令并重新核对代码与版本，以用户最新要求和 PRD 为业务依据。本任务文档只拆解实施，不自行改变 PRD；涉及未确定的实质业务取舍时先报告差异和具体方案，普通实现选择由执行者解决。

执行规则：

1. 从 **XNR-001** 开始。一个任务的全部依赖为 DONE，且其环境/合同条件满足后，才能开始该任务的修改。
2. 指定“执行 XNR-014”时只完成该任务；指定“执行 R04”时按依赖完成该批，不自动扩到 R05。完成任务后更新状态、证据和下一可执行任务。
3. 表中路径是当前核实过的入口或明确标注的计划产物，允许按实际职责重构；每次执行前重新检查，不以保留类名或现有测试名称为目标。
4. 每项任务实施前列清实际文件、表/状态变化、是否产生 Story Event、事务、幂等、重复 Job、中途退出、恢复和验证方法。任务卡提供起点，具体新增字段/类按 XNR-002 的合同落实。
5. 依赖通过不等于后续功能通过。R03 可使用测试替身验证编排，R04 接入真实实现后必须在 R05 重新做全链验证；测试替身不能进入真实生成链。
6. 不因文档编写而现在删除代码、清理业务数据、停止服务或发起收费请求。实际执行按已授权范围推进；真实模型费用沿用明确授权，额度缺失时只阻塞收费部分并完成其余准备。
7. 所有任务修改代码时必须增加或同步更新中文注释；修改数据库时必须增加或同步更新中文备注，具体要求见第 1.3 节。此要求适用于全部任务，不因单张任务卡未重复列出而省略。

### 1.1 状态和完成条件

任务总表是状态的唯一权威记录；任务卡不重复维护状态。首次状态仅 XNR-001 为 READY，其余为 TODO，均未完成。

| 状态 | 使用条件 |
| --- | --- |
| TODO | 尚未开始，或依赖未完成 |
| READY | 依赖及必要输入已具备，可执行 |
| IN_PROGRESS | 已开始，记录执行者、开始时间和当前断点 |
| BLOCKED | 存在明确缺失的权限、预算、环境或业务决定；写清原因、解除条件和已完成工作 |
| DONE | 实施、适当验证、审查与文档同步均完成，证据已记录 |

每项 DONE 必须有实际结果，不能只写“代码已写”“测试文件存在”或“建议人工验证”。记录通过、失败、跳过和未运行；业务必需的 PostgreSQL/真实模型检查没做时，对应验收任务不能标 DONE。测试失败或后续改动使结论失效时重新打开任务，保留原验证记录。

### 1.2 统一完成检查

- 变更与本任务需求一致，没有平行的旧/新权威入口或重复配置来源。
- Draft 不污染正式状态；需要正式写入时只通过统一提交/受控修正入口。
- 重复执行、来源过期、暂停及中途退出有明确结果和验证。
- 新模型请求可追踪费用；人工动作与 AI 修复遵守同一版本和授权规则。
- 必要测试实际执行，相关架构/运维文档同步，新增无用代码和失效引用已处理。
- 本次新增或修改的代码已补充准确的中文注释；数据库结构变更的中文备注已随迁移落库并核实，不能仅在迁移源码中写注释。
- 留下代码范围、数据影响、验证证据、限制和恢复步骤；无需改动的模块也有审查依据。

### 1.3 中文代码注释与数据库备注

**代码注释：** 新增或修改类、方法及业务逻辑时，必须在相应位置增加或更新中文注释，说明职责、业务含义、关键规则和设计原因。事务边界、幂等身份、状态转换、来源校验、失败恢复、费用限制等容易误用的逻辑必须有清晰说明。PHP 优先使用中文 PHPDoc，复杂分支补充必要的中文行内注释；类型、标识符和技术术语保持准确，不要求翻译代码名称。

注释必须与最终实现一致。修改逻辑时同步修订已有注释，删除代码时清理失效注释；不能仅写“处理数据”“执行操作”等空泛说明，也不通过逐行复述语法增加噪声。删除无用代码不要求给已经删除的内容补注释，但保留下来并被修改的实现仍须符合本要求。

**数据库备注：** 新增业务表必须有中文表备注和中文字段备注；修改现有表或字段时，必须补充或更新受影响对象的中文备注，受影响表缺少表备注时一并补齐。备注应说明业务用途；状态字段注明取值含义，金额/字数/时间字段注明单位或口径，关联字段注明关联对象，快照或 JSON 字段说明内容范围及版本含义。必要的索引和约束说明其保障的业务规则。

数据库备注必须通过迁移或统一初始化方案写入数据库元数据，不能仅存在于 Migration 的 PHP 注释或数据模型文档中。字段重命名、类型/含义调整和回滚时同步维护备注；删除字段时清理对应文档。仅执行数据修复而不改变结构时，修复代码与操作记录使用中文说明目的、影响和恢复方式，不额外改写无关 Schema。

**验收：** 代码审查检查本次变更的中文注释是否完整、准确；数据库变更在隔离 PostgreSQL 中执行迁移或初始化后，读取实际表/字段备注核对，有回滚路径时同时核对回滚结果。执行记录填写注释与备注的检查范围、结果和证据。未满足本节要求的任务不得标记 DONE；纯文档任务注明“不涉及代码或数据库变更”。

**需求：** §1.3、§2、§11.1；P01–P15。

**代码入口与范围：** `docs/PRD.md`、`app/Services/`、`app/Actions/`、`tests/`、现有业务记录与日志（只读）。

实施步骤：

1. 记录代码提交、工作区变更、实际依赖和当前运行入口；逐条核实 P01–P15，区分历史样本、当前缺陷和未复现风险。

**数据、事务与幂等：** 只读生产/现有业务数据；新增本地脱敏夹具与报告，不改变任务、队列和正式故事状态。

**验证与完成条件：** 每个已确认问题有代码位置或完整关联证据；无法复现的项明确注明。夹具不依赖旧数据库在线且无凭据。旧日志不可用时记录缺口，用已确认合同构造测试，不能伪造历史响应。

**失败恢复：** 撤回新增报告/夹具即可；不得为采样重试、提交或修复旧小说。

**交付物：** 拟新增 `docs/development/reports/XNR-001-baseline.md`；测试夹具按测试目录惯例存放。

**失败恢复：** 修改设计版本和依赖任务输入；未定的合同不进入对应编码任务，不阻止无依赖的调查。

**交付物：** 拟新增 `docs/architecture/generation-workflow.md` 与 `docs/architecture/data-model.md`，包含完整合同及模块映射。

### XNR-003 建立隔离 PostgreSQL 与队列测试环境

**批次与依赖：** R01；XNR-002。

**需求：** §2 P15、§11.3、§13.2。

**代码入口与范围：** `phpunit.xml`、`tests/Pest.php`、`tests/TestCase.php`、`config/database.php`、`config/queue.php`、`config/horizon.php`。

## 5 验证方法与命令边界

当前仓库使用 Pest，`composer test` 会先执行配置清理再调用 Laravel 测试；`phpunit.xml` 默认是 SQLite 内存库且队列同步。本任务计划不把它视为 PostgreSQL 事务、部分唯一约束、JSONB 和真实队列恢复的验证结果。

XNR-003 要交付独立 PostgreSQL 测试配置和目标库保护。下列命令是该配置创建并验证隔离之后的执行示例，本轮未运行；若测试因重构更名，使用任务交付中记录的等价测试文件，不保留已废弃行为只为沿用文件名。

```bash
vendor/bin/pest --configuration phpunit.pgsql.xml tests/Feature/CanonicalCommitServiceTest.php
vendor/bin/pest --configuration phpunit.pgsql.xml tests/Feature/ChapterPipelineOrchestrationTest.php
vendor/bin/pest --configuration phpunit.pgsql.xml tests/Feature/AutomaticGenerationRecoveryTest.php
vendor/bin/pest --configuration phpunit.pgsql.xml
```

执行前确认配置实际加载了隔离 PostgreSQL，而非被原 phpunit 环境变量或缓存覆盖。同步队列测试不能替代 Worker 进程退出/重复投递专项；后者由 XNR-005/026 的隔离 Redis 与 Worker 测试实施。

按变更范围使用以下检查；PHP 格式化按执行时有效的开发指令运行，避免误改其他工作区变更。不把无关重复全套执行当作进度：

```bash

```

新建未跟踪文档还应单独检查链接、表格、编号和空白；普通 `git diff --check` 不覆盖全部未跟踪文件。依赖安装、迁移、队列清理、Worker 切换和真实调用的具体命令由 XNR-003/025/027 在识别环境后写入手册，不提供可误打现有业务库的通用清空命令。
